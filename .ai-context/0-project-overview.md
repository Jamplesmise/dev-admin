## 2. 核心目标

### 2.1 解决的核心问题

FastGPT 旨在解决以下问题：

1. **LLM 应用开发门槛高** - 普通用户/企业难以快速构建基于大语言模型的应用
2. **知识库与 LLM 结合复杂** - RAG (检索增强生成) 实现需要大量技术积累
3. **工作流编排困难** - 复杂的 AI 工作流需要编写大量代码
4. **多模型管理繁琐** - 企业需要对接多个 AI 提供商，管理复杂

### 2.2 产品价值主张

```
让每个人都能快速构建 AI 应用，无需编程知识
```

**核心能力**：
- **可视化工作流** - 通过拖拽节点构建复杂 AI 应用
- **开箱即用的 RAG** - 知识库创建、向量检索、混合检索、重排序
- **多模型支持** - 统一接口对接 OpenAI、Azure、文心一言、通义千问等
- **丰富的集成方式** - API、Iframe 嵌入、免登录分享、MCP 协议

## 5. 项目边界

### 5.1 FastGPT 做什么 (In Scope)

- AI 应用的可视化构建与编排
- 知识库的创建、管理与检索
- 多模型的统一调用与管理
- 对话历史的存储与管理
- 应用的分享与嵌入
- OpenAPI 兼容接口
- MCP (Model Context Protocol) 服务端/客户端
- 基础的用户、团队、权限管理
- 用量统计与计费

### 5.2 FastGPT 不做什么 (Out of Scope)

| 不做的事情 | 原因 / 替代方案 |
|------------|-----------------|
| **训练/微调模型** | 专注应用层，模型由外部提供 |
| **通用 BI 分析** | 超出产品定位 |
| **实时音视频** | 复杂度高，可通过插件扩展 |
| **移动端原生 App** | 优先 Web，移动端通过响应式支持 |
| **离线运行** | 依赖外部 AI 服务 |
| **自研向量数据库** | 使用 PostgreSQL/Milvus |

### 5.3 技术边界约束

```yaml
禁止引入:
  - 新的前端 UI 框架 (已锁定 Chakra UI)
  - 新的状态管理库 (已锁定 Zustand + Context)
  - 新的数据库类型 (已锁定 MongoDB + PostgreSQL/Milvus)
  - 非 TypeScript 的后端代码

慎重考虑:
  - 新增大型依赖 (需评估包体积影响)
  - 修改数据库 Schema (需迁移脚本)
  - 修改 API 接口契约 (需向后兼容)
```

## 7. 关键业务流程

### 7.1 知识库构建流程

```
1. 创建数据集 (Dataset)
2. 创建集合 (Collection) - 对应一个数据源
3. 导入数据:
   ├─ 文件上传 (PDF/Word/TXT/MD/HTML/CSV/XLSX)
   ├─ URL 抓取
   ├─ 手动输入
   └─ API 推送
4. 数据处理:
   ├─ 文本提取
   ├─ 分块 (Chunking)
   └─ QA 拆分 (可选)
5. 向量化:
   ├─ 调用 Embedding 模型
   └─ 存储到向量数据库
6. 就绪可用
```

### 7.2 工作流执行流程

```
1. 用户发起对话请求
2. 加载应用配置 & 工作流定义
3. 从起始节点开始执行:
   ├─ 解析节点输入 (变量替换)
   ├─ 执行节点逻辑 (AI调用/知识库检索/HTTP请求等)
   ├─ 输出结果
   └─ 根据边连接决定下一个节点
4. 循环执行直到结束节点
5. 聚合结果返回用户
6. 记录对话历史 & 用量
```
