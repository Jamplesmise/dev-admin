## 二、数据流向 (Data Flow)

### 2.1 用户请求完整链路

```
用户输入
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│ 1. 前端层                                                        │
│    Browser → React Component → API Request (TanStack Query)     │
└───────────────────────────┬─────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│ 2. API 路由层                                                    │
│    NextJS API Route → 鉴权中间件 → 参数校验 → 业务Handler        │
│    路径: projects/app/src/pages/api/                            │
└───────────────────────────┬─────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│ 3. 服务层                                                        │
│    @fastgpt/service → MongoDB/Redis 操作 → 外部API调用          │
│    路径: packages/service/core/                                  │
└───────────────────────────┬─────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│ 4. 数据层                                                        │
│    MongoDB (业务数据) / Milvus (向量) / Redis (缓存)             │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 工作流执行数据流

```
用户触发工作流
    │
    ▼
┌──────────────────────────────────────────────────────────────────────────┐
│  1. 入口解析                                                              │
│     ChatController → 解析 App 配置 → 提取 WorkflowNodes + Edges          │
│     路径: projects/app/src/pages/api/v1/chat/completions.ts              │
└────────────────────────────┬─────────────────────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────────────────────┐
│  2. 工作流调度器                                                          │
│     dispatchWorkflow() → 构建执行图 → 确定执行顺序                        │
│     路径: packages/service/core/workflow/dispatch/index.ts               │
└────────────────────────────┬─────────────────────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────────────────────┐
│  3. 节点执行循环                                                          │
│     for each node:                                                        │
│       ├─ 获取输入数据 (从上游节点或用户输入)                              │
│       ├─ 调用节点 Dispatcher (如 dispatchChatCompletion)                  │
│       ├─ 执行节点逻辑 (AI调用/数据库查询/代码执行等)                      │
│       └─ 输出数据 → 传递给下游节点                                        │
│     路径: packages/service/core/workflow/dispatch/                        │
└────────────────────────────┬─────────────────────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────────────────────┐
│  4. 结果聚合                                                              │
│     收集所有节点输出 → 组装最终响应 → SSE 流式返回                        │
└──────────────────────────────────────────────────────────────────────────┘
```

### 2.3 知识库检索数据流

```
用户问题
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│ 1. 问题向量化                                                    │
│    Text → Embedding Model → Vector [1536维]                     │
│    服务: packages/service/core/ai/embedding/                    │
└───────────────────────────┬─────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│ 2. 向量检索                                                      │
│    Vector → Milvus/PgVector → Top-K 相似文档                    │
│    服务: packages/service/core/dataset/search/                  │
└───────────────────────────┬─────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│ 3. 重排序 (可选)                                                 │
│    候选文档 → Rerank Model → 重新排序                           │
│    服务: packages/service/core/ai/rerank/                       │
└───────────────────────────┬─────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│ 4. 上下文组装                                                    │
│    检索结果 → 拼接 Prompt → 传入 LLM                            │
└─────────────────────────────────────────────────────────────────┘
```

## 三、模块边界 (Module Boundaries)

### 3.1 包职责划分

| 包名 | 职责 | 依赖 | 禁止 |
|------|------|------|------|
| **@fastgpt/global** | 类型定义、常量、纯工具函数 | 无外部依赖 | 禁止数据库操作、HTTP 调用 |
| **@fastgpt/service** | 数据库操作、外部服务调用、业务逻辑 | global, mongoose, ioredis | 禁止前端代码、UI 组件 |
| **@fastgpt/web** | UI 组件、Hooks、样式、国际化 | global, react, chakra-ui | 禁止数据库操作、Node API |
| **projects/app** | 应用组装、API 路由、页面渲染 | global, service, web | - |
| **projects/sandbox** | 代码安全执行 | 独立隔离 | 禁止访问主数据库 |

## 六、扩展机制

### 6.1 工作流节点扩展

新增节点需要修改:
1. `packages/global/core/workflow/template/system/` - 节点模板定义
2. `packages/global/core/workflow/node/constant.ts` - 节点类型枚举
3. `packages/service/core/workflow/dispatch/` - 节点执行逻辑
4. `projects/app/src/pages/api/core/workflow/` - API 接口(如需要)

### 6.2 AI 模型扩展

模型配置通过数据库管理，支持动态添加:
- LLM 模型: Chat Completion 兼容接口
- Embedding 模型: 向量化接口
- Rerank 模型: 重排序接口

### 6.3 插件机制

支持两种插件形式:
1. **工作流插件**: 封装为可复用的工作流模板
2. **MCP 插件**: 符合 MCP 协议的外部工具
